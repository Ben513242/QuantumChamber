# M1.2 單人供電與原艙保護實作計畫

> **執行代理要求：** 使用 superpowers:subagent-driven-development，逐任務執行、測試與評審。步驟以核取方塊追蹤。

**Goal:** 單人可先從外部供電保護艙體，再進入關門補齊藥水自動 ARMED；斷電安全協調後僅原艙解除保護，另提供可選手持火把照明啟動方式。

**Architecture:** 紅石輸入、資格、供電保護與 session 介面分離。Registry 保留碰撞占位，保護依完整來源身分與獨立供電狀態判定；M1.2 使用明確無走廊的 session adapter，M2 再接入真實服務。

**Tech Stack:** Minecraft 1.21／Fabric／Java 21／Gradle 8.8／JUnit 5／Fabric GameTest。

**Spec:** `docs/superpowers/specs/2026-09-17-m1.2-powered-origin-design.md`。

## Global Constraints

- Minecraft 1.21、Yarn 1.21+build.9、Fabric Loader 0.17.2、Fabric API 0.102.0+1.21、Fabric Loom 1.7.4、Java 21、Gradle Wrapper 8.8。
- 單一 Fabric module，維持 main／client 分離及 `splitEnvironmentSourceSets()`。
- 外殼 7×7×7、內部 5×5×5、Controller local(3,6,0)、25 格 Bulkhead；三種建材、ID、青紫造型不變。
- 不新增 Universe、Dimension、走廊、傳送、renderer、自訂 packet、mandatory 第三方依賴或 `LICENSE`。
- 僅 `feature/m1-chamber`；不 push／merge main，不刪玩家世界、不修改 `run/client-base/saves`。
- 中文說明與程式註解一律繁體中文；只用 apply_patch 編輯來源及文件。
- `Enabled` 是管理狀態，不是供電；保留舊 UUID／管理旗標。OFF 解除保護不解除 Registry 碰撞占位。
- 只有完整核對的原艙可解除保護／拆除；RETURNING、UNKNOWN 與失敗狀態不得先解鎖。
- main 不載入 client／第三方照明類別；server baseline、client-base 不安裝選用照明模組。

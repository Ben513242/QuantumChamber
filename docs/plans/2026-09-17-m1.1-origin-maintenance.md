# M1.1 紅石提交與 Origin 維護實作計畫

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 新艙體只在成功紅石邊緣註冊，並提供安全的 Origin 停用與創造模式拆除。

**Architecture:** 將唯讀 readiness 與註冊提交分離，只有真正 rising edge 呼叫提交。Origin 維護以 Registry 身分驗證為核心，Controller 實際移除成功後才解除記錄與跨 chunk 保護索引；不改持久化 schema。

**Tech Stack:** Minecraft 1.21、Yarn 1.21+build.9、Fabric Loader 0.17.2、Fabric API 0.102.0+1.21、Fabric Loom 1.7.4、Java 21、Gradle Wrapper 8.8。

**Spec:** `docs/implementation-notes/m1.1-contract.md` 為本次核准契約；既有 `docs/quantum_superposition_chamber_design.md` 的其他幾何、保護與里程碑界線維持。

## Global Constraints

- Minecraft 1.21、Yarn 1.21+build.9、Fabric Loader 0.17.2、Fabric API 0.102.0+1.21、Fabric Loom 1.7.4、Java 21、Gradle Wrapper 8.8。
- 單一 Fabric module，維持 main／client 分離及 splitEnvironmentSourceSets()。
- 外殼7×7×7、內部5×5×5、Controller local(3,6,0)、25格Bulkhead；原本三種建材與青紫模型保留。
- INVALID=0、IDLE=3、READY=7、ARMED=11；15不使用。
- 不新增 Universe、dynamic dimension、corridor、teleport、projection materialization、Session、renderer、bloom、動畫或自訂packet。
- 真實foreign／unknown ServerWorld live coverage仍延至M3，不為M1.1物化外部世界。
- 不新增LICENSE；不合併或推送main。使用者既有feature/m1-chamber為本次工作分支。
- 使用繁體中文新增註解、操作訊息與報告；不變更生存模式 hardness／drops。
- 每個任務先記錄實際 RED，再最小 GREEN；只提交自己的檔案，不派子代理、不 push、不停止使用者既有遊戲程序。

## 檔案責任

- `ChamberActivationService`：資格唯讀評估與成功提交，不處理維護輸入。
- `ChamberRedstoneService`：邊緣與狀態；非 rising 路徑不註冊。
- `ChamberRegistry`／`ProjectionIndex`：既有記錄唯讀查找、移除紀錄及所有 chunk 索引。
- `ChamberOriginAuthority`／`ChamberLifecycleService`：Origin 身分與生命週期，不依賴玩家 UI 或 client。
- `ChamberMaintenanceInteraction`：server-authoritative 原生輸入轉接、受限 Controller 移除與結果訊息。
- testmod 的 `M11PersistenceProbe`：僅測試用的跨程序重啟探針，不進 release JAR。
- 指引、SVG 與 PNG：由總指揮同步維護，任務代理不得編輯這些檔案。

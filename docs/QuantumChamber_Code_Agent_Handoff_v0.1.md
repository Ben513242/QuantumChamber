## 6. 未來旅行設計不可漏掉

Root Anchor 是盒子起源；Entry Endpoint 是本趟出發端。B 出發取消／SOURCE 返回 B，HOME 才是 A。新路由意圖必須版本化，不重解釋舊收據。B 出發的 same-seed／toggle 以 B 的已確認生成設定為來源，不要錯用根錨 A 的 seed／preset。

返根錨目標可能是 vanilla A，不能偽造 catalog U；不得對原始 A 艙執行 Projection FIRST_WRITE 而清掉其物品。重啟後重新解析 live world，不把舊 instance token 當永久權威。同一 Chamber 的多端點先採一次一個 session。

旅行 capability 不得冒用 FamilyCapabilityVersion。根錨未知、斷電、摧毀須分開；已抵達玩家不能被追溯拉回或消滅。這些都應先進獨立 binding spec，然後才改 production。

「本輪玩家可見改變 → 保持不變的契約 → 實際修改檔案／格式 → 實際測試與證據 → 未執行驗收／限制 → 下一個最小切片」。

## Fabric 事件基線限制

額外安全檢查先發現模組 callback 的 candidate query 早於原生距離限制，要求移至 player-world／距離／高度／權限／loaded guard 後。進一步獨立 bytecode 查證：range與loaded guard本身不載入，原生 too-far helper也不查方塊；實測 event invoker仍載入並不能歸因於 vanilla。

真正來源由本機 Fabric sources 與逐 listener 診斷共同證明：interaction-v0 0.7.12+ba9dae06d1 的 `InteractionEventsRouter.java:onInitialize` 第28行無條件 `world.getBlockState(pos)`，一般情況第40行 PASS。模組自己的 handler PASS後 chunk仍未載入，下一個框架router PASS後已載入。**因此只保證模組自己的 callback 不增加非法輸入查詢，不聲稱整個 Fabric event／wire 不強載 chunk。** 專屬邊界測試選取真正已註冊 handler、名稱標明 own callback，仍需 guard 回退 RED→GREEN；有效 lifecycle與非法距離保護測試仍用原生入口。不修框架、不重排event、不加Mixin／packet，也不把真實foreign ServerWorld提前帶入M1.1。

Task 1 最終 log 有一筆 vanilla `Can't keep up`（2416ms／48 ticks）；未找到 ERROR／Exception，所有斷言與正常 shutdown 通過。已列為 final review 待判讀的非阻擋 timing warning，不把自動測試綠燈外推為性能保證。

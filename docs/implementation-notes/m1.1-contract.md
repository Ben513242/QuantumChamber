# M1.1 核准契約：紅石提交與 Origin 維護

核准日期：2026-09-17。基準提交：`4f96569`。本文件記錄使用者已在對話核准的行為，不宣告程式或人工驗收已完成。

## 固定環境與範圍

- Minecraft 1.21、Yarn 1.21+build.9、Fabric Loader 0.17.2、Fabric API 0.102.0+1.21、Fabric Loom 1.7.4、Java 21、Gradle Wrapper 8.8。
- 單一 Fabric module，維持 main／client 分離及 splitEnvironmentSourceSets()。
- 外殼7×7×7、內部5×5×5、Controller local(3,6,0)、25格Bulkhead；原本三種建材與青紫模型保留。
- INVALID=0、IDLE=3、READY=7、ARMED=11；15不使用。
- 不新增 Universe、dynamic dimension、corridor、teleport、projection materialization、Session、renderer、bloom、動畫或自訂packet。
- 真實foreign／unknown ServerWorld live coverage仍延至M3，不為M1.1物化外部世界。
- 不新增LICENSE；不合併或推送main。使用者既有feature/m1-chamber為本次工作分支。

## 1. 新建艙體只在成功紅石邊緣提交

1. 結構完成後是未註冊草稿；沒有Chamber UUID／Registry record，因此不套用已註冊volume保護。創造模式仍可修改／拆除。
2. 週期refresh、falling edge、開關門、chunk load／restart，只能讀取與預覽readiness，不建立Registry紀錄或新UUID。
3. 草稿有效但條件不足為IDLE／3；有效、門關閉且所有完整位於interior的非spectator玩家都有QuantumState時，可預覽READY／7。零參與者不得READY。
4. 只有真正unpowered→powered rising edge，且上述前置條件、Registry健康與同role不重疊成立，才註冊／resolve Origin UUID、套用volume保護並進入ARMED／11。
5. 無效shell／門未關／零人／任一缺buff／Registry loadError／重疊拒絕，都不得為新艙體留下Registry record或UUID。
6. 放置或載入時已held-high只同步latch，不製造edge；ARMED不消耗buff，不傳送。
7. 已成功註冊的艙體不因玩家離開／buff到期／power變低而自動解除保護，仍須維護停用／拆除。

## 2. Origin 維護

- 一般右鍵Controller：維持整面門開／關，即使設備停用仍可操作門。
- 雙手空手＋蹲下右鍵Controller：切換Enabled↔Disabled。持物蹲下維持Minecraft放置物品語意，不搶走放拉桿／比較器操作。
- 操作僅server-authoritative；spectator、PROJECTION或身分不匹配不得操作。
- 權限由Origin身分決定，不新增玩家個人owner／OP規則：核對BE UUID與instance kind、record kind／UUID、current world key／DimensionRole、Controller位置／facing、Registry健康與record非destroyed。
- 維護不要求shell完整，避免損壞艙體無法復原；但必須有可核對的原Origin Controller與record。未註冊草稿的維護不得偷偷註冊。
- 停用立即為INVALID／0、禁止arming，保留UUID／record／全部volume保護；普通紅石pulse不能改enabled。
- 重新啟用只回到當下READY／7或IDLE／3，不把held-high當新edge；需新的低→高才ARMED。
- 操作提供簡潔繁體中文結果／拒絕原因，不新增GUI或自訂packet。

## 3. 創造模式兩階段拆除

1. 已註冊且Enabled的Origin Controller不可普通拆除。
2. 先停用，再由創造模式玩家左鍵Controller，觸發模組維護拆除；不能靠「所有disabled volume都允許普通寫入」來實作。
3. 拆除再次核對完整Origin身分；只授權移除該Controller。其他volume位置仍受保護直到本次拆除成功。
4. Controller世界移除失敗／throw／身分拒絕時，Registry與索引必須保持，不提前解除保護。
5. Controller確實移除後，才刪該Origin Registry紀錄、移除所有相交chunk的ProjectionIndex entry並markDirty；BE／原load-sync queue entry失效。不得留下ghost protection／同role collision。
6. 其餘基岩與Bulkhead不自動刪除；解除保護後由創造模式普通拆除。原生基岩與沿用基岩強度的兩個mod方塊仍不保證生存模式可挖，不改其hardness／drops。
7. 沒有record的草稿維持普通創造模式破壞；不新增生存維護工具／配方。
8. 拆Controller後在同位置重建可取得新的UUID，但仍必須新的有效紅石edge才註冊。舊UUID不可重用，不刪任何世界。

## 4. 既有世界與驗證

舊schema1紀錄不自動清除或推定從未ARMED：現有資料不能可靠區分舊版自動註冊與真正啟動過的艙體。保留既有UUID／enabled／record；可維護停用、拆Controller並重建以走新註冊流程。本次不改schema／做破壞性migration。

必須保留原生紅石與玩家互動GameTests、純JVM registry／authority／失敗回復測試、disabled／dismantled跨程序重啟證據、dedicated Done→stop與無client class loading error。最後clean build與所有GameTests綠燈；人工滑鼠／HUD／多人仍要實際觀察，不以direct helper冒充UI。

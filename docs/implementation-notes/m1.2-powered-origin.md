## 實際行為與界線

有效原艙可以先在外部供電：空艙、開門仍取得 UUID 與保護。玩家入艙、關門且全員具 QuantumState 後，持續高電位自動 `ARMED`。管理旗標 `Enabled` 與獨立供電狀態分開；管理停用不等於解除高位保護。

斷電先安全協調返還，確認成功才進入 `OFF`，比較器為0、原艙允許修改。此時保留 UUID 與碰撞占位，重新供電使用同一 UUID；只有真實成功移除 Controller 才清除 Registry 與全部相交 chunk 索引。`RETURNING`、`UNKNOWN` 與失敗狀態保留保護。schema1 保留既有欄位並讀為保守 `UNKNOWN`；schema2 另存供電狀態，損壞資料拒絕正常使用與覆寫。

M1.2 當時的 adapter 是 `NONE`／`ARMED_ONLY`，不消耗效果、不傳送。M2 的 Session、走廊與 Universe 當時尚未實作（其後由 M2–M4 接續，現況見 README）；本版沒有新增動態 Dimension、自訂 packet 或 renderer。7×7×7外殼、5×5×5內部、25格整面門及三種建材不變。

## 最終修正：載入安全與指引一致性

原生 PersistentStateManager 會將底層讀取例外轉為空值。Registry 現在只有明確確認 `.dat` 不存在才初建；檔案存在卻未成功載入，或檔案狀態不可確定時，拒絕啟動。全新 `run/m12-final-fix` 隔離 fixture 分別重現截斷 gzip、非法 gzip、合法壓縮但非法 NBT，以及 `.dat` 為目錄造成的原生讀取失敗；四項均先 RED 後 GREEN。GREEN 均為正式健康例外、沒有正常 tick、Java 實際 0／外部預期拒絕 1。前三項直接核對 `.dat` SHA256 不變；目錄案例確認型別與其中 `preserve.txt` 的 SHA256 不變，不宣稱目錄有檔案雜湊。

schema2 的 OFF 繼續保存，但每次載入的 runtime 拆改許可先鎖定。排入 load-sync 會撤回舊許可；原艙身分、實際電位與返還協調完成後才恢復。普通 remove 與創造模式維護拆除共用該 gate，後者不能經 target authorization 繞過。UUID／Enabled／索引及成功移除才清理的契約不變。

固定 1.21 的 weak、實心鄰格 strong、紅石線連線查詢，在讀電位前要求水平正負三格所覆蓋的 chunk 已 FULL。缺少鄰區不當成低位，queue 保留 pending 與保護並重試。兩個原生反例均確認 C 已 FULL、鄰區在查詢前後仍未 FULL；明示載入缺少鄰區後才完成 OFF 協調與拆除。這不宣稱任意第三方紅石查詢的相容性。

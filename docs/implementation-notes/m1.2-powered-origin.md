# M1.2 供電原艙與驗證紀錄

日期：2026-09-17。Minecraft 1.21／Fabric Loader 0.17.2／Fabric API 0.102.0+1.21／Yarn 1.21+build.9／Loom 1.7.4／Java 21／Gradle 8.8。

## 實際行為與界線

有效原艙可以先在外部供電：空艙、開門仍取得 UUID 與保護。玩家入艙、關門且全員具 QuantumState 後，持續高電位自動 `ARMED`。管理旗標 `Enabled` 與獨立供電狀態分開；管理停用不等於解除高位保護。

斷電先安全協調返還，確認成功才進入 `OFF`，比較器為0、原艙允許修改。此時保留 UUID 與碰撞占位，重新供電使用同一 UUID；只有真實成功移除 Controller 才清除 Registry 與全部相交 chunk 索引。`RETURNING`、`UNKNOWN` 與失敗狀態保留保護。schema1 保留既有欄位並讀為保守 `UNKNOWN`；schema2 另存供電狀態，損壞資料拒絕正常使用與覆寫。

目前 adapter 是 `NONE`／`ARMED_ONLY`，不消耗效果、不傳送。M2 的 Session、走廊與 Universe 尚未實作；本版沒有新增動態 Dimension、自訂 packet 或 renderer。7×7×7外殼、5×5×5內部、25格整面門及三種建材不變。

## 損壞資料的預期拒絕

新 `run/m12-corrupt` 在 SERVER_STARTING 寫入 wrapper `data` 下 `SchemaVersion=99`／空Records。PID17164的正式SERVER_STARTED健康guard擲出包含 `quantumchamber_chambers` 的 IllegalStateException，沒有進入正常tick；原始與退出後 `.dat` SHA256同為 `2c6230d832e01a85fd42a822eb7feab4bc41d880a5cac21b78c62548b2852a64`。

Pinned原生 `MinecraftServer.runServer` 捕捉例外並清理後返回，**實際Java exit0**；外部驗證器辨識拒絕並以**wrapper exit1**返回。此結果標為「expected negative verified」，與正常smoke分開。原生setup可能先印Done，所以Done或Java exit0都不是健康通過的充分條件；需同時核對正式例外、禁止正常tick與原始hash不變。沒有為測試增加production `System.exit`。

契約裁定後再於全新 `run/m12-corrupt-verified`、PID20252重現相同結果與相同hash，外部工具實際exit1；另保存 `negative.json` 明列 `expected negative verified`、Java0及wrapper1。
